# UI 方案定案（2026-09-16 八问）

> 这份文档是 **UI 部分的决策正本**。八条都是用户拍板的，不是我的建议。
> 相关：`decision-rendering.md`（渲染引擎取舍）、`design.md`（美术参数）、`architecture.md`（分层）

## 一句话

**路线 B：程序化 SDF 自绘。参考 ModernUI 的"自己写渲染引擎"做法，只取所需、不做前置。
画法收口成插槽，参数真源在 CSS token，靠一个游戏内 harness 迭代。**

## 八条定案

| # | 问题 | 定案 | 关键约束 |
|---|---|---|---|
| 1 | 自研边界 | **形状层 + 自己的批处理器**，不要 ModernUI 的框架层（View 树/生命周期/UI 线程/Markflow/Resources） | 我们的是 5~6 张不响应点击的卡，View 树解决的问题我们一个都没有 |
| 2 | 视觉参数真源 | **CSS token 是持续真源**：HTML 顶部只用 `--pc-*` 写标量，薄脚本抽成 `styles/default.json`，Java 读同一份 | 只搬标量（颜色/半径/描边/内边距/间隙/时长/缓动名）；**几何与文本相关的一律不进转换**；harness 滑条只读不回写 |
| 3 | harness 形态 | **完整调试屏**：样例卡集 + 几何辅助线 + 动画时间控制 + 背景切换 + GUI scale 验证 + 只读滑条 + 截图导出 | dev-only（`FMLEnvironment.isDevelopment()`）门控；**不许长成第二个 UI 框架**（滑条用我们自己的形状层画＝吃狗粮）；**不许当第二真源** |
| 4 | 设计保真 | **限定 CSS 子集，清单外报错、绝不静默**；`tools/css_tokens.py` 遇到清单外属性直接失败退出 | 静默失败是最毒的（上一版 AUI 的 `radial-gradient` 不解析且不报错） |
| 5 | 实施顺序 | **harness 壳 → 形状层 → 卡片画法 → 美术迭代**；`BaselineCardPainter` 从占位升格为**对照组** | 先建测试台，材料用最糙的；需求从工具里长出来，不先设计 API |
| 6 | 批处理批什么 | **统一入口 + 同 uniform 自动合并 + `stats()`**；不碰自定义顶点属性 | ~~坐标一律屏幕绝对值~~ → **跟随 `GuiGraphics.fill` 的 pose 语义**（见下方"实施修正"）；**形状层整体先于内容层提交**（`MultiBufferSource` 按 RenderType 分组，不是按插入序） |
| 7 | 谁判"好看" | **客观门 + 候选制 + 3 轮断路器** | 客观项（错位=0/任意 scale 锐利/5 卡不重叠/超长名不越界/60fps）不过就不聊视觉；视觉我出 3 版候选你选；3 轮不行＝方向问题，停下重定，不继续磨 |
| 8 | 卡宽边界 | 上限 `min(屏宽 × 0.45, 240px)`；`Font.plainSubstrByWidth` 像素级截断 + `…`；名字区加下限 ~40px；**NEW 改为入场时的一次性光晕脉冲**（不占布局） | 全名看不到了——HUD 卡不接受悬停，tooltip 兜不了，这是**认下的信息损失** |

## M1 已完成：形状层落地（2026-09-17）

对 1.20.1 字节码核实了四件事，全部有据：

1. **`apply()` 不重置自定义 uniform** —— 它遍历全部 uniform 调 `upload()`，而
   `upload()` 只在 dirty 时上传。所以"先 set 再 draw"是**对的**，uniform 会在 flush
   那一刻随 `apply()` 上传。
2. **`Tesselator.end()` 就是 `BufferUploader.drawWithShader(builder.end())`** —— 归档版
   的入口本身就是正规 vanilla 入口，"整层不可见"不在入口上。
3. ⚠️ **真正的静默陷阱**：`safeGetUniform(名字)` 在名字不存在时返回的是
   `AbstractUniform`——一个 `set(float)` 字节码为 `return` 的**空实现**。打错名、或某个
   uniform 被 GLSL 优化掉，都会变成"set 全丢、不报错、不日志"。这正是老 bug 的形状。
   现在 `ShapeShaders.uniform()` 会按名字**尖叫一次**。
4. **`RenderType.create` 是包级私有**，自建 RenderType 需要 AT —— 除非继承 `RenderType`
   用它的 protected 构造器（ModernUI 的 `GuiRenderType` 就是这么做的）。我们照做，
   blend/cull/depth 交给声明式 `RenderStateShard` 清单（框架成对 setup/clear），
   取代归档版手写却没配对还原的 `RenderSystem` 开关。

**spike 结果：六个图元全部画出，几何逐像素命中（误差 ≤1px），双色渐变正常，
"整层不可见"没有复现。** 读数 `shapes=6 flushes=6 merges=0`。

### 实施中的两处修正（与原计划的差异）

- **坐标语义改为跟随 `GuiGraphics.fill`**（当前 pose 空间），不再要求"一律屏幕绝对"。
  真正要守的不变量是"**一个 painter 的一趟绘制里只有一种坐标空间**"；跟随 `GuiGraphics`
  是最不会搞错的那种，因为原版所有绘制代码都是这个语义。
- **"同 uniform 合并"的实际收益比预想小**：spike 里六个图形尺寸各异、零合并。
  真实卡面能合并的是同尺寸的强调色条与圆徽章。1.20.1 上 uniform 是 per-draw，
  要真合批就得把参数搬进自定义顶点属性——那是这个版本有名的坑，不做。

## 与上一版的关系

上一版 `archive/selfdraw-v2` 的 shader **技术是对的**（`sdRoundBox` + `aastep`，与 ModernUI
同款算法），它死在**美术没定稿 + 手算坐标 + 没做真机验收**。所以这次复用它的着色器思路，
但补上它缺的三样：参数真源、辅助线、快速真机循环。

两条前车之鉴写在 `decision-rendering.md` 的"死路"一节：**HTML 当贴图**、**绝对/局部坐标混用**。

## M2 定案（2026-09-17 续）

### 已定

- **卡片版式**：三段式 —— `稀有度竖条 ｜ 物品图标格 ｜ 名字 + 数量框`，三个独立圆角矩形等高。
  稀有度只体现在最左那根竖条上，不再是整张卡身的强调色。
  旧版那套（胶囊卡身 / 双圈描边 / 出头圆徽章 / 名字内嵌胶囊 / 右端端点 / 左外月牙 / NEW 角标）
  全部作废，主题里对应的死字段一并删除。
- **入场动画**：竖条**原地出现并展开**，其余部分从竖条右侧**滑出**；卡片自身尺寸全程不变
  （是位移，不是拉伸）。新卡从上方插入，把旧卡往下挤。
  实测：竖条坐标全程恒定、内容自身宽度全程恒定、可见部分 0 → 188。
- **默认对齐**：**右边缘对齐**（卡片右缘固定，左缘随内容长短伸缩，内容再长也不出屏）。
  固定 X 的锚点模式保留为配置项。
- **阴影**：走 **SDF 软化距离场**（`u_soft` uniform），不新增 pass、不新增 RT。
  把抗锯齿宽度从 1 像素换成 blur 半径，小半径下近似真高斯；有效区间约 0~8px，
  再往上衰减形状会失真（真高斯在拐角糊得更圆），届时应改走离屏模糊。

### 硬规则：配置里一律说人话

**配置项的名字与注释是玩家唯一会直接读到的文字，必须用字面描述，不许用比喻、
内部代号、黑话。** 例如"竖条是隧道口、卡片是火车"这类说法只存在于设计讨论里，
落到 TOML 就必须写成"内容保持完整，从左边滑出来"。

配套的第二条：**一个键只能有一个家**——同一件事绝不允许两个配置文件都能改，
那就是第二真源（上一版正是死在这上面）。

## 阴影：根因缩小 + 权宜绕过（2026-09-17）

**症状**：本批**第一次**提交的形状渲染成**不透明**（顶点上的 alpha 被丢掉），第二次之后全部正常。

### 怎么缩小的

同一种半透明黑（`0x5A000000`）在棋盘底上做受控对照（棋盘格是天然判据：真混合会透出两种格子色）：

| 实验 | #1 | #2 | #3 | #4 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 原版 `gui.fill` | 正常 | — | — | — | 原版路径没问题 |
| 直角 / 圆角 交替 | **黑** | 正常 | 正常 | 正常 | — |
| **顺序对调**（圆角先、直角后） | **黑** | — | — | — | **黑块跟着"顺序"走，不跟着半径走** |

顺序实验推翻了先前"半径 0 才会黑"的判断（那只是巧合）。

**触发条件**：这一次 draw 之前发生过一次**别的 RenderType** 的绘制。
卡片页每张卡的第一个形状是阴影，前面是上一张卡的图标/文字 → **五张卡的阴影全黑**，
位置正好是阴影露在卡片下方的那几条边。这也解释了为什么症状看起来像"模糊没做好"。

**已排除**：
- SDF 软化宽度（`u_soft`）为 0 —— 不是，见上表
- 未冲刷的原版缓冲 —— 在本批第一次形状前插 `endBatch()` 无效
- 直角/圆角差异 —— 顺序实验推翻
- `aastep` 里 `w` 可能取 0 导致 `smoothstep(0,0,dis)` 的 0/0 —— 顺手加了 `max(fw, 0.5)`
  下限（这是真隐患，但不是本症状的原因）

### 权宜绕过（当前生效）

`ShapeBatch` 在本批第一次提交前，先往**屏幕外**（坐标 −100000）丢一个退化矩形，
让"坏掉的那一次 draw"自己去坏。之后用户提交的形状全部正常。

**这是权宜之计，不是修复。** 真修好之后 `ShapeBatch.warmUp()` 应当删掉。
它不负面作用已实测：卡片页纯黑像素从 16791 降到 116（余下是物品贴图自身的深色像素），
五档强调色采样仍精确，卡下阴影是平滑渐变而非黑块。

### 仍然没做的事

1. 定位真正的状态泄漏源。下一步应在 `RENDER` 层核
   `RenderType.end()` 前后 `setupRenderState/clearRenderState` 的配对与执行顺序，
   特别是非形状层 RenderType 的 `clearRenderState` 之后有哪个 GL 状态没还原。
2. 阴影现在走 SDF 软化（`u_soft`），有效区间约 0~4（对应实际模糊 8px），再大衰减形状会失真。

## 测量页与客观门（2026-09-17 续二）

### 做了什么

三件东西，互相咬着：

| | 干什么 | 为什么 |
| --- | --- | --- |
| `design/measure.py` | 看图算数（纯函数） | 与 CLI 分开，才能拿"已知答案的合成图"去钉它 |
| `design/test_measure.py` | 合成图量回来必须是真值；另有"像素扫描 vs 浏览器 DOM 矩形"端到端自检 | **在拿尺子量真东西之前，先量一个我知道多长的东西** |
| `design/measure.html` + harness 的 `pickupcard-measure` 页 | 两边各出一张"纯黑底、无辅助线、无读数、无装饰"的测量页 | 对照的输入必须可重复 |

`python design/compare.py 设计图 游戏图 --expect 4` 的输出分成三段：
**输入检查 / 差异表 / 客观门**。纯底占比 < 40%、两边卡数不一致，一律直接拒收并说明原因 ——
拿任意截图的量不出东西。

### 一个被推翻的旧诊断

v1 的"条-卡体间距"判据是"从竖条右缘往右找第一个比竖条暗 75% 的像素"。
竖条比卡体**亮**，所以条件在第一个像素就不成立 → 该指标**恒等于 1px**，与真实间距无关。
`docs/handoff.md` 与本文早先把它归因于"投影把间隙填住了" —— 那个诊断是错的。
真相是合成图测出来的：16px 的真实间隙，v1 判据量出 0px，新判据量出 16px。

### 客观门的结果（先记下来，作为回归基线）

`measure.png`（设计，1280×960，dsf 4）vs `pickupcard-measure`（实现，854×480，guiScale 2）：
**结构项全部一致，误差 0.000** —— 竖条宽 0.156、竖条高 0.875、两处间隙各 0.125、
图标格宽 1.000、级差 1.188、固定边都是右对齐。

这个"一致"不是同义反复：两边是**两个独立实现**（浏览器 CSS 引擎 vs 我们自己的 Java painter）
读同一份 `tokens.css`。它证明的是"游戏确实按 token 把几何画对了"，
证明不了"这套美术好看"—— 后者是 M3，只有用户能点头。

### 门之外还差什么（逐条列给用户确认）

| 差异 | 现状 / 待定 |
| --- | --- |
| 顶部高光线 | 设计稿有（`--pc-highlight`），Java 侧零引用 → **参数白生成了**。要画还是删？ |
| 经验卡图标 | 设计稿是下界之星贴图，实现是 8×8 强调色方块。设计意图是"星" |
| 强调色 | `RarityAccent` 硬编码，与主题各存一份（当前值相同）。要不要收进主题？ |
| 字体语言 | 客户端 `en_us`，草稿写中文名 → 卡宽差异有一部分来自这里 |
| `BaselineCardPainter` | 无人引用，且 `ICON_PX * iconSize()` 是 `iconScale` 时代的残留（算出 384px）。建议删 |

### 测量环境的两条硬规矩

1. **纯黑底**。投影是半透明的黑，叠在纯黑上等于没叠，自己就消失 ——
   于是不用为测量往渲染里加"关投影"的开关（那会是 `--pc-shadow-alpha` 的第二真源）。
   **选对测量环境，比给测量加开关便宜。**
2. **窗口固定 854×480**。全屏 2560×1600 时 `Screenshot.grab` 出的四张图互不相同、
   却都不含任何卡（guiScale=6）。改窗口前先确认截图里真有卡。

## 参考图实测（2026-09-17 续三）

用户给了一张参考图（`design/reference/paste.png`，624x633）。它**不是**测量页，
所以 `compare.py` 会拒收；用 `design/probe.py` + 一次针对性的量法把它读了出来。

### 它是什么

| 线索 | 读数 |
| --- | --- |
| 底色 | `#202028` / `#2C2C36` 棋盘格，格子恰好 36 设备px |
| 强调色 | 五个**全是我们 tokens.css 里的值**，顺序：uncommon / common / rare / xp / epic |
| 卡 | 5 张，三段式；卡高 96、级差 114、间距 12、图标格 96 |
| 文字 | 读出来是「2字名+1」「2字名+64」「5字名+99999」「2字名+137」「2字名+1」—— 与我们 fixture 里那几件物品对得上 |

把 96/3=32、36/3=12 一代进去，**整张图就是我们的主题放大 3 倍**：卡高 32、图标格 32、
间距 4、级差 38、棋盘格 12 —— 全对。

### 与我们的差异（同尺度同判据）

| 项目 | 参考图 | 我们的实现 | 结论 |
| --- | --- | --- | --- |
| 对齐 | **左缘固定**（竖条左缘极差 0，右缘极差 4） | 右缘固定（极差 0 / 边长随名字变） | **最大的一条** |
| 竖条宽 / 卡高 | 16/96 = **0.1667** | 15/96 = 0.1562 | 差 1 个设备像素 |
| 竖条高 / 卡高 | 84/96 = 0.875 | 0.875 | 一致 |
| 上下内缩 / 卡高 | 6/96 = 0.0625 | 0.0625 | 一致 |
| 两个间距 / 卡高 | 12/96 = 0.125 | 0.125 | 一致 |
| 图标格宽 / 卡高 | 96/96 = 1.000 | 1.000 | 一致 |
| 级差 / 卡高 | 114/96 = 1.1875 | 1.1875 | 一致 |
| 框内顶部高光 | **没有** | 实现没有；**设计稿 CSS 里有** | 我们的**草稿**多画了一条 |
| 经验卡图标 | 有图标（不是纯色块） | 实现画一块 8x8 强调色方块 | 实现少画了 |

### 怎么得到的这三条结论

- **对齐**：竖条左缘 0 极差 + 卡右缘 4px 极差 ⇒ 左缘固定。用我们的构建验证过：
  `stickTo=LEFT` + `leftEdge=16` 得到「左缘极差 1px、右缘极差 81px」，同一种结构。
  也就是说**参考图的版式是配置能到的，不需要改代码**（`stickTo=LEFT` 单独设不够：
  在 426 逻辑宽下 `leftEdge=320` 会让卡片被右边界夹住，退化成右对齐）。
- **高光**：逐行扫框内顶部。设计稿第一行是 (98,99,105) 然后掉到 (39,42,51) ——
  一条 `inset 0 1px 0` 的亮线；实现与参考图都是从亮到暗平滑衰减，**没有那条线**。
- **竖条那 1px**：参考图竖条是 16 个**满**像素、两侧没有半覆盖；我们 guiScale=3 时是
  13 满 + 两侧各 0.74 覆盖率 ≈ 14.5 设备px。所以是**真的**宽了约 0.5 逻辑像素，
  不是量法噪声。（顺带发现：我们形状层的竖条比逻辑尺寸**窄**约 0.3~0.5 设备像素。）

### 这一轮同时在测量工具里修掉的两个真 bug

1. **一根竖条被两个强调色同时认领。** 青色竖条的边缘像素（青底各半）实测 (43,118,128)，
   到**灰色** common 的距离是 202，到青色自己却是 286 —— "离谁近就归谁"于是把一根青条
   同时判给 rare 和 common，4 张卡量出 6 张。修法不是改分类，而是**看条心**：
   两个候选重叠时留"中心像素更像它"的那个。
2. **物品贴图里也能凑出"又高又窄的一列"**，而且它左边也有底色（图标格的缝）。
   加一条更强的约束：**竖条是这张卡最左边的东西** —— 凑出来的那些左边还有图标格边框。

### 环境：GUI 缩放被窗口尺寸夹住

`guiScale` 设 3 在 854x480 上**不生效** —— MC 会把缩放夹到窗口放得下的最大值（2）。
现在客户端跑测固定 `--width 1280 --height 720`（`build.gradle`），自动缩放正好 3：
一张卡 32 逻辑px -> 96 设备px，测量分辨率从 1.6% 升到 1.0%。

### 还没定的事

- 参考图要的是**左对齐**，而 M2 定的是**右对齐** —— 这是唯一需要用户拍板的结构差异
- 竖条那 0.5 逻辑像素：改成 5.5px（或按卡高的 1/6）还是保持 5px
- 顶部高光线：**删掉草稿里那条**（跟着实现和参考图），还是给实现补上
- 经验卡图标：实现补一个图标，还是草稿改成纯色方块

## 用户拍板（2026-09-17 续四）

看完 `design/ref-vs-impl.png` 与差异表之后定的四条：

| # | 问题 | 定案 | 代价 |
|---|---|---|---|
| 1 | 对齐 | **左缘固定**（改掉了 M2 的右缘） | 配置默认值两处 + 设计稿一行 |
| 2 | 竖条宽 5px 还是 5.33px | **保持 5px**（用户说"不知道"，判据见下） | 零 |
| 3 | 顶部高光线 | **补到实现里**（设计稿有、实现没有） | 画法里加一条 1px |
| 4 | 经验卡图标 | **加**：下界之星 | 画法里一行 |

### 1) 左缘固定

`LayoutSettings.defaults()` 与 TOML 的默认值都改成 `LEFT` / `leftEdge = 16`；
`design/measure.html` 跟着改成左缘对齐（不改的话客观门立刻会在"固定的是哪条边"上红）。

**`leftEdge` 从 320 降到 16 不是顺手改的**：它是**软目标**，放不下就往左让。
426 逻辑宽的 GUI 上设 320，卡片会全被右边界夹住，于是"左对齐"实际渲染成右对齐 ——
实测就是这么发生的（第一次只改 `stickTo` 完全没效果）。
**一个设了等于没设的值，比没有这个值更坏**：它让人以为已经改过了。
16 取的是右缘固定模式下的右边距，两种模式因此对称。

### 2) 竖条宽：保持 5px（这是判断，不是偷懒）

参考图是 16/96 = 1/6；我们是 15/96 = 5/32 = 0.15625。判"不改"的理由：

- **5 是手写的数，5.33 不是。** 32 的六分之一写不出来是设计意图，只会是渲染的产物。
- **同一份 tokens 的两个独立实现都给出 15**：浏览器 dsf=3 和游戏 guiScale=3 都量到 15 设备px。
  两份渲染器一致，说明主题说的就是 5px，而不是我们两个实现一起偏了。
- **它会制造一个隐藏耦合**：写成"卡高的 1/6"就把竖条宽度绑死在图标尺寸上 ——
  以后把图标从 24 调到 32，竖条会**悄无声息**变宽。那是第二真源的又一个入口。
- 这 1px 在 96px 卡高上是 1.04%，肉眼在 `ref-vs-impl.png` 里要盯着看才分得出。

**但顺带查出来一件事，与 5px 无关**：我们的形状层把 5 逻辑px 的竖条画成
guiScale=2 时 ≈9.7 设备px、guiScale=3 时 ≈14.5 设备px —— **比逻辑尺寸窄 0.3~0.5 设备像素**。
参考图是 16 个满像素、两侧没有半覆盖；我们两侧各有一个 0.74 覆盖率的像素。
这是形状层的事，和 `warmUp()` 一起在形状层那轮处理。

### 3) 顶部高光

`TrioCardPainter` 里新增 `topHighlight()`：每个框在渐变底之上、描边之下画一条 1px 的
`--pc-highlight`。顺序与 CSS 的叠法一致（`box-shadow: inset` 在底色之上、`outline` 之下）——
顺序反了高光会被描边压掉一半，看起来"画了但没效果"。
alpha 为 0 就是不画，沿用主题里这个键本来的语义，**没有新增开关**。

### 4) 经验卡的图标

经验卡没有 `ItemStack`，原先画一块强调色方块占位。现在固定渲染下界之星。

**依据不是"我觉得好看"**：参考图里经验卡那一格的主导色是
`#556B6B` / `#88A4A4` / `#B9C9C9`，与 `design/icons/nether_star.png` 的三个主色**逐个相同**。
实测补上之后，把图标区域打成亮度图，是一个**四角星**、核心是 `#FFFFD2`（下界之星的淡黄芯）✓

## 用户拍板（2026-09-17 续五）：默认什么都不丢

**起因是实测**：捡到沙子（`minecraft:sand`）→ 屏幕上什么都没有，日志里一个字也没有。

原来 `FilterRules` 里有一张"内置忽略表"（dirt / cobblestone / cobbled_deepslate / gravel /
sand / red_sand / netherrack / wheat_seeds），默认开启、命中即丢弃。它的本意是别让挖一片
海滩把屏幕刷满，但实际效果是：**玩家的观感是"mod 坏了"** —— 而这两件事长得一模一样。

### 定案

- **内置忽略表整张删除**，`useDefaultIgnoreList` 这个配置键也不存在了。
  **默认每一次拾取都弹卡**，包括泥土、圆石、沙子。
- 想安静由玩家自己写 `[filter] blacklist`（默认空），规则写法不变。
- 万一被黑名单丢掉，日志里会说清楚是它干的、怎么放行（每个物品只报一次）。
- `muteList` 保留不动：它只压声音，不藏卡，和这条不冲突。

### 为什么这么定

"**不替玩家决定该看见什么**"比"替他省掉几张卡"重要。那张表自己的注释原本就写着
"宁可让玩家偶尔看到一张圆石卡，也不要替他静音掉本想看见的东西" —— 而它当时吞掉的正是
玩家可能真想看见的东西，且完全无声。**故意 ≠ 可以无声。**

### 顺手补的一道验证

`-PharnessAuto=hud`：注入样例、**不打开调试屏**，让 HUD 自己画，并打印在屏的是哪几张卡。
之前所有自动截图都走调试屏那条路，而调试屏（`Screen.render`）和 HUD（`RenderGuiEvent.Post`）
**只是共用 `CardStage.renderInto`，不是同一条触发路径** —— 这次"没弹窗"的报告正好踩在这个盲点上。

## 用户拍板（2026-09-17 续六）：引擎、尺寸、排版、动画、配置界面

这一轮的拍板大多不是"选一个"，而是**用户看到实物之后指出"没照草稿"**。按发生顺序记，
因为每一条的判据都是它前面的那条留下的：

| # | 问题 | 定案 | 代价 / 备注 |
|---|---|---|---|
| 1 | 渲染器 | **引入一个高级轻量的矢量引擎** = NanoVG（`org.lwjgl:lwjgl-nanovg`，与 MC 的 LWJGL 同版本）。SVG 由绑定自带的 NanoSVG 解析（解析是纯 CPU 的，能离线单测） | 绑定 + 四平台 native 约 1MB；SDF 层整条保留作回退 |
| 2 | 卡片太大 | **框缩到字的大小**：卡高 32 → 22（图标 16 = 原生 1:1、上下内边距各 3），其余长度按同一比例缩以保住参考图量出来的比例 | 字/卡 25% → 32%。**不放大字**：MC 字体固定 8px，非整数放大就糊 |
| 3 | 卡片跑左下角 | 锚点改**顶锚**（草稿 `animation.html` 是 `TOP_Y=16` 往下排） | `StackLayout` 去掉底锚；`guiHeight` 参数随之删除 |
| 4 | 新的把旧的顶上去 | **最新的一张排最上面**，旧的被往下挤（草稿是 `slots.unshift`） | `live` 反序 + 换位过渡 `CardMove` |
| 5 | 动画生硬 | 去掉整卡缩放与 `easeOutBack` 过冲（草稿里新卡是**原地出现**）；补 340ms 换位过渡；曲线用草稿那条 `cubic-bezier(.22,.9,.28,1)`（`CubicBezier` 真解，不是近似） | 时长 620 → 560ms，正好让 30%/18% 两个分段还原草稿的 180/100/460 |
| 6 | 阴影廉价 | 改成**按轮廓逐元素投**（竖条 + 图标格 + 名字框），不再用一个包住整卡的大矩形 | 软边仍是 SDF smoothstep 近似，**不是**高斯；且测量页纯黑底 → 阴影从来没被量过（见 handoff 盲点一节） |
| 7 | 配置界面 | 键位 **K** 打开，两列 16 项 + 实时预览；存储是 TOML `[style]` 段，每项可 **-1 = 跟随主题** | 主题给默认值、配置只覆盖改过的项 → 不产生第二真源。预览走真卡绘制代码 |
| 8 | 打包 | **自包含**：绑定 + 四平台 native 直接摊进 jar（附 `THIRD_PARTY_NOTICES.md`） | JarJar 要 Maven 风格版本区间（写 `3.3.1` 配置期就失败），且玩家侧能否加载在本机验不了 |
| 9 | 部署 | 覆盖 `D:\Myworld\.minecraft\versions\1.20.1-main\mods\pickupcard-Forge-1.20.1-0.2.0.jar` | 运行中的实例不会热加载，改完必须重新 build 覆盖 |

### 为什么第 3、4 条值得单独记一笔

它们**不是"没调好"，是"没照草稿"**：草稿的排版语义写得很清楚（顶锚、新卡在队首、旧的往下挤），
而代码是底锚 + 老的在上面 —— 正好两条全反。更值得记的是**门禁没能拦住它**：
`compare.py` 逐张比卡片结构（竖条宽/高、间距、圆角、级差），**不比对卡堆的锚点与顺序**，
所以这种"整段排版都不对"的错误一路绿灯，是用户截图才暴露的。

**结论**：门禁的判据要覆盖"用户一眼就能看出来的东西"，而不只是它能算的那几项。
下一步补两条零成本指标：`首卡上缘 / 卡高`（抓锚点）、`强调色自上而下的顺序`（抓谁在最上面）。

### 后续：形状层那个 bug 已经修了（2026-09-17 续六补记）

上面第 134 行与第 303 行写的"`warmUp()` 是权宜之计、真修好后必须删"——**已经修完并删掉了**。
真根因是 `gui_shape.json` 里没有 `"blend"` 块（`ShaderInstance.apply()` 会调 `blend.apply()`，
缺省构造出来的是 opaque=true 的 `BlendMode` → `disableBlend()`），
而 `BlendMode.lastApplied` 是**static** 缓存，所以只有"与缓存不同"的那次 apply 真正生效 ——
表现就是"本批第一次不透明"。细节与验证方式见 `docs/handoff.md` 第 0 节。
**别再按"RenderType 配对顺序"那条路去查**，那是当时的错误方向。

### 后续：渲染路径收口成一条（2026-09-17 续七补记）

上面决策表里那句"**SDF 层整条保留作回退**"以及 M1 那一整段"形状层"（`ShapeBatch` +
`gui_shape` 着色器 + `warmUp()`）**都已经不存在了**：用户对着四条并存的画法（原版渲染 /
DOM 草稿当贴图 / SDF 着色器 / NanoVG）说了一句"我们的项目不干净"，于是把卡面的绘制收到
一处 —— **影子 / 微光 / 竖条 / 两个框 / 入场裁剪全在 NanoVG 里**，SDF 形状层、SDF 整卡
回退、`CardPainter` 插槽接口一起删除。

本文件里 M1 那一节的形状层实现细节因此只当**历史**读；现行结构看
`docs/architecture.md` 的"渲染路径：只有一条"。唯一从 M1 活下来的判断是
"**先建测试台（harness + 像素门禁），再从工具里长需求**"—— 那条被证明是对的。
